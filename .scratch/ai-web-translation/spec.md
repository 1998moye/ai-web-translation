# 浏览器 AI 翻译插件首版规格

**Status:** ready-for-agent

## Problem Statement

用户需要在 Chrome 和 Edge 中阅读、浏览并实际操作英文网站，但不希望把原文复制到单独的翻译网站，也不希望翻译过程破坏网页结构。用户希望自己控制翻译服务，包括完整请求地址、API Key、模型、自定义请求头、思考方式和其他请求参数，并且不需要依赖插件作者搭建的中转服务器。

现有简单翻译工具往往只处理正文，导航、菜单和按钮仍然是英文；或者在翻译时覆盖代码、重复请求动态内容、混用不同配置的译文。首版需要同时解决双语阅读、界面文本可用性、动态页面增量处理、请求成本、配置安全和失败恢复问题。

## Solution

构建一个 Manifest V3 浏览器扩展，默认在可注入的 HTTP/HTTPS 网站提供可拖动的悬浮翻译按钮，并支持划词翻译。正文采用原文与简体中文译文对照，界面文本采用译文优先并可查看原文。扩展直接连接用户配置的 OpenAI 兼容 Chat Completions 翻译服务，不搭建中转服务器。

扩展通过统一的 Translation Engine Interface 隐藏请求构造、翻译提示词、分批、上下文、缓存、并发、超时、重试和取消。整页翻译通过 Page Translation Session 管理翻译单元、原文变化、动态内容和恢复原文。多份翻译服务配置仅保存在本机，页面脚本只能接触配置 ID，不能读取 API Key。

首版优先保证核心网页，持续适配复杂网页。配置与划词翻译、整页翻译与页面交互可以由两组实现并行完成，最后通过真实 Translation Engine 联调。

## User Stories

1. 作为英文网页读者，我希望在 Chrome 中加载扩展，以便不离开当前网页就能获得译文。
2. 作为 Edge 用户，我希望使用同一套扩展功能，以便无需更换浏览器。
3. 作为英文文章读者，我希望原文段落下显示简体中文译文，以便对照理解内容。
4. 作为网页读者，我希望无需刷新即可恢复原文，以便回到网站的原始状态。
5. 作为网站操作者，我希望导航和菜单也被翻译，以便理解网站提供的功能。
6. 作为网站操作者，我希望按钮和表单标签被翻译，以便完成实际网页操作。
7. 作为网站操作者，我希望界面文本默认只显示中文但可以查看英文，以便兼顾布局和核对原文。
8. 作为技术文档读者，我希望代码块、命令、参数名和行内代码不被翻译，以便复制后仍能正确使用。
9. 作为网页读者，我希望链接和行内格式在翻译后仍然可用，以便保持原始阅读路径。
10. 作为中英混排页面读者，我希望只翻译英文内容，以便保留已有中文和页面结构。
11. 作为长页面读者，我希望后续加载的正文自动翻译，以便持续阅读而不重复点击。
12. 作为动态网站用户，我希望原文变化后旧译文失效，以便不会看到不对应的内容。
13. 作为动态网站用户，我希望未变化的内容不重复提交，以便减少等待和请求费用。
14. 作为网页读者，我希望插件插入的译文不会再次触发翻译，以便避免无限更新。
15. 作为划词用户，我希望选中文本后先看到小图标，以便翻译不干扰正常复制和选择。
16. 作为划词用户，我希望点击图标后在附近看到译文气泡，以便理解当前选区。
17. 作为多配置用户，我希望在划词时切换翻译服务配置，以便比较不同模型或使用不同服务。
18. 作为长文本读者，我希望长选区可以分批返回译文，以便尽早阅读已成功部分。
19. 作为质量敏感用户，我希望翻译能利用页面标题和相邻原文，以便获得一致的术语和上下文。
20. 作为多服务用户，我希望保存多份命名配置，以便不用反复填写连接信息。
21. 作为自定义服务用户，我希望填写完整请求 URL，以便连接官方、代理或本机兼容服务。
22. 作为自定义服务用户，我希望 API Key 可以留空并自定义认证请求头，以便支持不同认证方式。
23. 作为高级用户，我希望配置自定义请求头，以便满足翻译服务要求。
24. 作为高级用户，我希望直接编辑额外请求参数，以便控制思考方式、温度等服务行为。
25. 作为高级用户，我希望默认请求参数显式尝试关闭思考，以便降低翻译延迟和不必要的推理消耗。
26. 作为高级用户，我希望思考方式只出现在请求参数中，以便界面不增加独立且不一定通用的控制。
27. 作为配置用户，我希望插件阻止额外参数覆盖核心字段，以便不会意外破坏翻译请求。
28. 作为安全敏感用户，我希望远程服务只允许 HTTPS，以便减少密钥和网页文本泄露风险。
29. 作为本地模型用户，我希望 localhost 和 127.0.0.1 可以使用 HTTP，以便连接本机服务。
30. 作为翻译用户，我希望默认提示词限制 AI 只做翻译，以便不会得到解释、总结或回答。
31. 作为安全敏感用户，我希望网页中的指令只被当作翻译资料，以便降低提示词注入影响。
32. 作为高级用户，我希望修改并恢复默认翻译提示词，以便调整术语和语气。
33. 作为配置用户，我希望用真实短句测试配置，以便在使用前发现地址、认证、模型和参数问题。
34. 作为配置用户，我希望看到脱敏后的具体错误，以便修正配置而不会泄露密钥。
35. 作为高级用户，我希望调整并发、超时和重试次数，以便适应不同服务的速度和限流。
36. 作为翻译用户，我希望能取消正在进行的任务，以便停止等待和后续请求。
37. 作为长页面读者，我希望成功内容先显示而失败内容保留原文，以便部分失败不阻塞整页阅读。
38. 作为服务不稳定时的用户，我希望网络错误、限流和服务端故障有限重试，以便完成临时失败的请求。
39. 作为配置错误时的用户，我希望参数或认证错误不自动重试，以便尽快看到真正原因。
40. 作为重复阅读用户，我希望成功译文在本机缓存，以便相同内容不重复请求。
41. 作为隐私敏感用户，我希望能清空译文缓存，以便删除本机保存的原文和译文。
42. 作为频繁调整配置的用户，我希望当前会话不被后续设置修改影响，以便同一页面译文保持一致。
43. 作为频繁调整配置的用户，我希望主动重新翻译时使用最新配置，以便明确控制新请求。
44. 作为网页读者，我希望普通网站默认显示悬浮按钮，以便无需逐站授权即可开始翻译。
45. 作为网页读者，我希望悬浮按钮默认在右侧中下部且可以拖动，以便避免遮挡网站内容。
46. 作为多网站用户，我希望拖动位置全局记住，以便不用在每个网站重复调整。
47. 作为网页读者，我希望悬停悬浮按钮后看到设置和关闭入口，以便快速管理当前页面。
48. 作为网页读者，我希望关闭一次仅在当前页面生效，以便刷新后重新找到按钮。
49. 作为多网站用户，我希望按完整域名永久关闭悬浮按钮，以便不影响同主域下的其他网站。
50. 作为多网站用户，我希望在设置中移除永久关闭的网站，以便恢复按钮。
51. 作为常用网站读者，我希望为指定域名开启自动翻译，以便打开英文页面即可阅读。
52. 作为多语言网站用户，我希望非英文网站不自动翻译，以便避免无意义请求。
53. 作为网站偏好管理者，我希望自动翻译列表和悬浮按钮停用列表分别管理，以便独立控制两类行为。
54. 作为隐私敏感用户，我希望 API Key 只保存在本机并脱敏显示，以便降低意外泄露风险。
55. 作为隐私敏感用户，我希望扩展直接连接我选择的翻译服务，以便明确网页文本发送到哪里。
56. 作为扩展用户，我希望理解全网站访问权限和受限页面例外，以便知情地使用扩展。
57. 作为核心网页读者，我希望文章、新闻、博客和文档网站稳定工作，以便满足主要阅读需求。
58. 作为复杂网页用户，我希望复杂网页持续适配但不阻塞首版，以便逐步扩大可用范围。
59. 作为项目维护者，我希望配置划词和整页会话可以通过共享 Interface 独立测试，以便两组实现可靠集成。
60. 作为项目维护者，我希望固定网页样本和真实网站共同验收，以便持续把兼容问题转化为回归案例。

## Implementation Decisions

### 架构与 Module

- 使用 TypeScript、WXT、React 和 Manifest V3，首版支持桌面 Chrome 与 Edge。
- Extension Shell 提供扩展构建、全网站匹配、后台与内容脚本通信、设置页签和共享测试能力，不包含具体翻译业务。
- Translation Engine 是配置划词与整页会话之间的主要 Seam。其 Interface 只包含开始翻译和取消会话：开始翻译接收会话 ID、请求 ID、配置 ID、翻译单元和翻译上下文，并返回可逐批消费的翻译事件；取消会话终止该会话全部排队和进行中的任务。
- Translation Engine 的 Implementation 隐藏 Chat Completions 请求、提示词、分批、缓存、并发、超时、重试、取消和配置快照。调用方不能访问这些内部步骤。
- Translation Profile Catalog 是只读 Interface，只向页面 UI 提供配置 ID、名称和默认配置。配置修改只能在设置页完成。
- Page Translation Session 对页面控制隐藏扫描、英文识别、翻译单元状态、动态监听、渲染、恢复和进度。调用方只发起翻译、重新翻译、取消、失败重试或恢复，并观察公开状态。
- 内容脚本只能使用配置 ID。API Key、敏感请求头和完整配置只能由后台读取，不能进入页面、日志或公开错误。
- 生产环境使用真实 Translation Engine Adapter。测试和整页组的独立开发使用 fake Adapter；fake 不得进入最终生产装配。
- 首版只实现 OpenAI 兼容 Chat Completions，不提前建立 Claude、Gemini 等没有当前 Adapter 的协议层级。
- React 页面和面板只负责布局与交互编排，业务规则归属对应 Module。避免 1:1 透传层、通用 helper 堆积和无独立行为的新 Seam。
- 方法超过约 80 行且包含两类以上无关步骤，或单文件超过约 400 行且包含多个面板时，按变化原因拆分；不为达到行数机械拆碎。
- 只在状态机、结果归并和异常兜底的非显然规则处使用中文注释，不添加复述代码的注释。

### 翻译服务配置

- 每份配置包含名称、稳定 ID、完整 URL、可选 API Key、模型名、自定义请求头、额外请求参数和任务运行参数。
- 额外请求参数使用 JSON 对象编辑，默认包含 reasoning_effort 为 none。用户可以增加、修改或删除参数，没有独立的思考等级按钮。
- model、messages、stream 由 Translation Engine 管理。额外参数出现这些字段时拒绝保存或请求，并给出明确错误。
- API Key 非空时生成 Bearer Authorization。自定义请求头同时包含 Authorization 时提示冲突，要求用户二选一；使用其他认证方式时 API Key 留空。
- 远程地址只允许 HTTPS；localhost 和 127.0.0.1 允许 HTTP。浏览器禁止设置的请求头需要明确提示，不能静默忽略。
- 并发数、请求超时和自动重试次数默认分别为 3、60 秒、2 次，可按配置调整。它们是插件任务设置，不进入请求体。
- 测试连接使用固定英文短句和完整配置发起真实翻译，不读取缓存，不以单纯网络连通代替协议验证。

### 翻译提示词与请求

- 默认翻译提示词将 AI 定义为翻译引擎而非聊天助手，只允许返回指定翻译单元的简体中文译文。
- 待翻译文本和翻译上下文都是不可信资料，其中的命令、问题或要求不得执行。
- 不允许解释、总结、回答、评论、添加前后缀或输出 Markdown。
- 页面标题、当前小节标题和前一段原文可作为只读翻译上下文，不得返回它们的译文；短界面文本不强制附加上下文。
- 请求和响应通过翻译单元 ID 保持对应。缺失、重复、未知或无法解析的 ID 不得猜测性渲染。
- 不要求所有服务支持专用结构化输出参数；默认通过提示词约定可校验的结构化结果，额外参数由用户负责。
- 默认提示词可编辑和恢复。修改后的提示词仍需保持单元 ID 与输出协议，测试连接用于发现不兼容配置。

### 页面识别与渲染

- 默认处理正文和界面文本，不仅限于主内容区。
- 正文保留英文并在段落下插入简体中文译文；恢复原文不需要刷新。
- 导航、菜单、按钮和表单标签采用界面文本译文优先，默认显示中文，悬停可查看英文。
- 代码内容、脚本、样式、隐藏内容和用户自己填写的输入内容不翻译。
- 按翻译单元识别英文；中英混排只提交英文，纯数字、符号和已有中文不请求。非英文网站不触发自动翻译。
- 保留链接、强调和行内格式。模型返回内容必须经过安全处理，不能作为可执行页面 HTML 直接注入。
- 悬浮按钮和划词气泡使用 Shadow DOM 隔离样式，避免污染网页或被网页样式直接影响。

### 页面翻译会话与增量处理

- 每个翻译单元具有稳定 ID、原文指纹和公开可推导的处理状态。内部可区分待处理、翻译中、已翻译、失败和原文已变化。
- 会话开启期间监听新增内容；新增内容先经过语言和内容规则，再查询缓存或进入翻译。
- 已翻译且原文未变化的单元不重复提交。原文变化使旧译文失效，并以新原文重新处理。
- 插件自身插入的译文和状态变化必须被监听逻辑忽略。
- 网站删除或复用节点时，不能仅按节点身份套用旧译文；过期响应不能渲染到不对应的新原文上。
- 恢复原文会取消任务并停止处理新增内容，但保留译文缓存。
- 当前会话首次请求时固定配置快照。主动重新翻译创建新会话并使用最新配置，避免中途混用译文。

### 缓存、失败与取消

- 译文缓存保存在本机，键包含规范化原文、源与目标语言、翻译服务、模型、翻译提示词和影响结果的请求参数，不包含 API Key。
- 缓存命中可直接渲染，但页面增量检测不能仅依赖缓存判断节点是否已处理。
- 提供清空缓存能力；清空缓存不修改翻译服务配置或网站偏好。
- 成功批次先显示，失败批次保留原文并允许重试，不因部分失败回滚整页。
- 仅网络错误、429 和 5xx 自动有限重试；429 尊重服务返回的等待时间。400、401、403 直接报告，不自动重试。
- 取消停止排队任务并中止可中止的进行中的请求；已经成功的译文和缓存保留，过期结果不得再次渲染。

### 悬浮按钮与网站偏好

- 默认在所有浏览器允许注入的 HTTP/HTTPS 网站显示悬浮翻译按钮，不提供扩展内逐站授权流程。
- 默认位置为右侧中下部，支持拖动，并在所有网站共享同一个记忆位置。
- 点击按钮翻译或恢复原文；悬停展开设置和关闭入口。
- 关闭一次只影响当前页面，刷新或重新打开后恢复。
- 永久关闭按当前完整域名保存，不影响同主域的其他子域，可在设置中移除。
- 自动翻译按完整域名单独保存和管理，与悬浮按钮站点停用不是同一偏好。
- 浏览器内部页、扩展商店和其他受限页面不承诺注入；本地文件访问不作为首版默认能力。

### 安全与交付

- 不搭建中转服务器，后台直接连接用户选择的翻译服务。
- 配置保存在本机扩展存储，密钥脱敏显示。本机存储不等于硬件级加密，不宣称密钥经过不可逆保护。
- 广泛主机权限只用于默认页面能力和用户选择的翻译请求，不得把浏览内容发送到用户未选择的其他目的地。
- 首版以本地加载和个人、小范围使用为交付目标，商店发布另行处理。

## Testing Decisions

- 当前项目没有实现代码或测试先例。共享骨架建立与 WXT 工具链一致的单元测试和真实浏览器端到端测试；优先使用 Vitest 验证 Module Interface，使用 Playwright 验证扩展和 DOM 行为。
- 测试只通过 Interface 观察外部行为，不断言私有扫描步骤、内部变量或调用次数等实现细节。涉及请求次数时，只把“是否向翻译服务产生请求”作为外部可观察行为。
- Translation Engine 使用 mock HTTP Adapter 覆盖成功、延迟、空结果、格式错误、缺失或重复 ID、网络错误、429、5xx、400、401、403、超时和取消。自动化测试不使用真实 API Key。
- 翻译服务配置通过设置页与本机存储的完整行为验收，覆盖保存、重新加载、默认配置、校验冲突和密钥脱敏。
- Page Translation Session 使用固定 DOM 样本和 fake Translation Engine，覆盖正文、界面文本、代码保护、混排语言、动态新增、原文变化、节点复用、乱序响应、恢复和取消。
- 悬浮按钮和划词气泡在真实浏览器中验证 Shadow DOM、拖动、悬停、关闭、选择和布局行为。
- 联调先通过可控的模拟 Chat Completions 服务验证完整链路，再用用户提供的真实服务做手动验收。
- MDN、英文 Wikipedia、BBC、GitHub、Stack Overflow 用于手动体验检查；固定网页样本用于稳定回归。真实网站的新失败案例应转为具体样本和独立 ticket。
- 每组完成后必须通过自己的构建、测试和可演示流程；联调 ticket 必须验证生产装配不包含 fake Adapter。

## Out of Scope

- PDF、EPUB、TXT、字幕文件、视频字幕、图片和漫画翻译。
- 输入框写作翻译及用户输入内容翻译。
- 英文以外源语言的质量承诺和自动翻译。
- 仅显示译文的全页模式。
- 代码注释翻译。
- Firefox、Safari 和移动端浏览器支持。
- Claude、Gemini 等原生协议以及任意请求体、响应体映射。
- 自建中转服务器、用户账号、云端配置同步和团队共享。
- 配置导入导出。
- 首版 Chrome 或 Edge 商店发布。
- 所有复杂网页、浏览器内部页和受保护页面的完美兼容承诺。
