# 16: 处理原文变化与页面节点复用

**What to build:** 使用翻译单元的原文指纹和状态识别网页对已有内容的修改，使旧译文失效并按新原文重新翻译。网站复用节点或返回乱序响应时，不得把旧译文套用到不对应的新内容。

**Blocked by:** 15: 翻译动态新增内容

**Status:** ready-for-human

- [x] 每个翻译单元记录用于变化检测的原文指纹，已翻译单元的原文变化会使旧译文失效。
- [x] 原文变化后的单元按新原文重新处理，不会继续把旧译文展示为当前原文的翻译。
- [x] 只有指纹发生有效变化时才重新处理，插件自身的译文插入、样式和状态变化不会触发重新翻译。
- [x] 网站复用 DOM 节点时，不仅凭节点身份判断原文未变，旧译文不会错误套用到新文本。
- [x] 原文连续变化时，只有最新原文对应的结果可以渲染，较旧请求返回后会被忽略。
- [x] 节点被移除或翻译单元不再存在时，相关结果不能渲染到无关节点。
- [x] 原文恢复为已缓存内容时可以复用有效译文，但缓存不能替代当前原文指纹校验。
- [x] 恢复原文后发生的内容变化不会重新启动翻译。
- [x] 使用动态样本覆盖原文修改、连续修改、节点复用、节点删除、乱序响应、缓存原文和自身 DOM 防重入。

## Comments

### 2026-11-17 实现完成

- 实现：每个翻译单元记录规范化原文指纹（FNV-1a + 长度）。重新扫描时：
  - 界面文本译文仍完整 → 视为未变化；
  - 指纹相同但译文被站点移除 → 用已有译文重渲染，不重复请求；
  - 指纹变化 → 旧译文失效、清理后按新原文重新翻译；
  - 节点移除或不再可翻译 → 清理记录与译文。
- 渲染前校验会话 ID、请求 ID、单元 ID、单元阶段与注册表身份，旧请求/旧原文的迟到结果不会渲染。
- 验收：`tests/unit/page-translation-session.test.ts`（正文原文变化、界面文本原文变化、节点复用、节点删除、迟到结果、译文被移除后重渲染、配置快照）；`tests/e2e/page-translation.spec.ts`（动态页原文被站点替换后译文更新，旧译文消失）。
