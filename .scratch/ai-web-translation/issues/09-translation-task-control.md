# 09: 完成翻译任务控制

**What to build:** 让 Translation Engine 的并发、超时、取消和自动重试真正生效，使用户能够停止长任务，并在临时服务故障时获得有限恢复，而配置错误不会被无意义地重复请求。

**Blocked by:** 08: 加入译文缓存与配置一致性

**Status:** ready-for-agent

- [ ] 每份配置的并发数得到执行，排队任务不会超过配置限制同时请求翻译服务。
- [ ] 请求超过配置超时时会中止并显示脱敏超时错误，不会无限等待。
- [ ] 取消会话会停止全部排队任务并中止可中止的进行中的请求，之后不会启动该会话的新批次。
- [ ] 取消前已经成功或写入缓存的译文保持有效，取消后的过期响应不能再次渲染。
- [ ] 网络错误、429 和 5xx 按配置次数有限重试，429 尊重服务返回的等待时间。
- [ ] 400、401 和 403 不自动重试，分别呈现可理解的参数或认证错误，并隐藏密钥和敏感请求头。
- [ ] 达到重试上限后进入失败状态，部分成功结果仍然可用，失败内容可以显式重新提交。
- [ ] 缓存命中不占用翻译服务并发，测试连接不被普通页面任务的缓存或重试逻辑意外改变。
- [ ] 使用可控 mock HTTP Adapter 验证并发、超时、取消、限流等待、重试上限、错误分类和乱序完成。
