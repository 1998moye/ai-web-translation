# 13: 完成界面文本译文优先显示

**What to build:** 将整页翻译扩展到导航、菜单、按钮和表单标签。界面文本采用译文优先显示，默认呈现中文并可按需查看英文，避免双语并列破坏网页布局。

**Blocked by:** 12: 完成正文整页双语翻译与恢复原文

**Status:** ready-for-human

- [x] 页面翻译会话将导航栏、菜单、按钮和表单标签识别为界面文本翻译单元。
- [x] 界面文本默认显示对应简体中文译文，不再要求原文与译文同时占据布局空间。
- [x] 用户悬停已翻译界面文本时可以查看对应英文原文，原文与译文对应准确。
- [x] 恢复原文后，所有界面文本恢复为原始英文，正文也保持可恢复。
- [x] 短菜单、按钮和导航项不会因为插入双语并列文本而明显撑宽、换行或遮挡相邻控件。
- [x] 界面文本原有的链接、点击和表单行为保持可用，译文不会阻止原事件。
- [x] 动态出现但尚未处理的界面文本不会在恢复原文时被错误改写。
- [x] 固定导航和表单样本在真实浏览器中验证译文优先、悬停原文、布局、交互和恢复行为。

## Comments

### 2026-11-17 实现完成

- 实现：界面文本单元在 `scanTranslatableTargets` 中独立识别（链接、按钮、菜单项、标签、legend、summary 等），渲染时用译文节点替换元素文本并记录原始节点，通过 `title` 提供英文原文；恢复时还原原节点与 title。
- 默认只显示中文译文，不插入并列文本；短标签不会被撑宽或换行；链接 `href`、按钮样式和表单行为保持不变。
- 验收：`tests/unit/page-translation-session.test.ts`（译文优先、悬停原文、恢复、原文变化重译）；`tests/e2e/page-translation.spec.ts`（导航链接/按钮/表单标签译文、title 原文、恢复、页面按钮背景色保持）。
- 已知限制：站点自建 tooltip 的 title 会被临时覆盖，恢复时还原。
